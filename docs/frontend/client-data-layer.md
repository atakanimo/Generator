# İstemci veri katmanı (mobil / web)

Mobil ve web istemcileri için **yalnızca veri katmanı** üretilir: tipler, servis çağrıları, RTK thunk'ları ve slice parçaları. Ekran / bileşen üretilmez. Kararlar ve açıklar: [§ Kararlar](#kararlar), [§ Açık konular](#açık-konular).

```
NormalizedModel v2 + manifest → resolveNormalApi (src/shared/normalApi.ts) → clientContext → client-redux şablonları
```

Kod: `src/main/generators/client-redux/` (`ClientGenerator.ts`, `clientContext.ts`, `clientPreset.ts`), şablonlar `src/main/templates/client-redux/`. Üretici BE stack'ini bilmez; yalnızca [api-contract.md](../api-contract.md)'ye göre yazar.

## Kaynak: normal uçlar

`resolveNormalApi(model)` (saf, `src/shared/normalApi.ts`) BE üreticileriyle aynı kuralları uygular:

- Operasyonlar: `api.normalOperations`; yazma işlemleri auth + ownership ister, `self` modelde create yok. Kapalı olanlar üretilmez, uyarı olarak döner.
- Ownership: `ownership.kind`, yoksa `userId` reference alanı → `field`. Owner alanı normal body'de ve filtrede yok.
- Okuma: `hidden` olmayan alanlar. Create / update: `readonly`, `adminOnly`, `hiddenFromCreate` / `hiddenFromUpdate` olmayanlar. Filtre: `searchable` ve `hidden` olmayanlar.

Express (`BackendGenerator.resolveNormalApi`, `zodFieldScoped`) ve .NET (`dotnetContext` `normalFields`) bu kuralları kendi içinde tekrar ediyor; biri değişirse üçü birlikte değişir.

## Dosyalar

Modül başına (`<x>` = entity adının camelCase'i: `Transactions` → `transactions`, `UserWatchList` → `userWatchList`):

| Dosya | Sahibi | İçerik |
| --- | --- | --- |
| `services/<x>.service.generated.ts` | Generator | `I<E>` (satır), `I<E>Saved` (create / update cevabı, ilişkiler id), `I<E>Input`, `I<E>UpdateInput`, `Get<E>Query`, `Get<E>ListBody`; açık operasyonların fonksiyonları `getAll`, `getById`, `create`, `update`, `delete<E>` |
| `services/<x>.service.ts` | Kullanıcı | `export *` + özel uçlar |
| `store/thunks/<x>.thunk.generated.ts` | Generator | Cevap / argüman tipleri, `<E>ThunkHooks`, `create<E>Thunks(hooks)` |
| `store/thunks/<x>.thunk.ts` | Kullanıcı | `<x>Thunks = create<E>Thunks({ … })`, thunk'ların export'u, özel thunk'lar |
| `store/slices/<x>.slice.generated.ts` | Generator | `<E>BaseState`, `<x>InitialState`, `<x>BaseReducers`, `merge<E>Saved`, `add<E>BaseCases(builder, thunks)` |
| `store/slices/<x>.slice.ts` | Kullanıcı | `createSlice`, actions, default reducer, `Get<E>State` |
| `services/api/common.generated.ts` | Generator | `ListPaginationBody`, `PaginatedList`, `RequestOptions`, `requestFlags`, `keepPopulated(All)`, `asFailure`, `responseThunk` (istemci başına bir) |

- Generator dosyası `// Auto Generated By Generator - <tarih>` ile başlar; gövdesi değişmedikçe yazılmaz (yalnızca tarih değişirse dosya yerinde kalır). Başlıksız dosya kullanıcınındır, üzerine yazılmaz.
- Kullanıcı dosyası yalnızca yoksa oluşturulur. Sonradan açılan bir operasyonun thunk'ı `<x>.thunk.ts`'deki destructuring'e elle eklenir.
- Operasyonu olmayan modülde (ör. yalnızca özel uçlu `dailyPortfolio`) yalnızca satır tipi üretilir; thunk / slice yok.
- Kullanıcı slice dosyası, `<x>.thunk.ts` `<x>Thunks` vermiyorsa oluşturulmaz (eski thunk dosyası); uyarı döner.
- **Root reducer'a dokunulmaz.** Yeni slice dosyası oluşunca sonuçtaki `notes` eklenecek satırları verir.

## Tipler (sözleşme §4, §5)

- `id: string`; tarih okumada `string` (ISO), yazmada `string | Date`; `decimal` `string`; enum değerleri literal birleşimi.
- İlişki okumada populate edilmiş obje: `{ id; <populate alanları> }`, alan tipleri hedef modelden (hedefteki ilişki id kalır, `hidden` alan alınmaz). Populate yoksa / `include` kapalıysa id. Yazmada her zaman id.
- BE'nin modelde olmayan alanları (ör. hesaplanan `nameInitial`) kullanıcı servis dosyasında modül genişletmesiyle: `declare module './users.service.generated' { interface IUsers { nameInitial?: string } }`.
- İstemcinin kendi kurduğu / ilişkiden gelen kısmi kayıtlar için gevşek tipler kullanıcı dosyasında (Varlik360: `SymbolRef`, `SymbolTypeRef`).
- Opsiyonel alan `?`; `nullable` ya da `default: null` ise `| null`. `.NET` arkasında (`optionalAsNull`) okumadaki her opsiyonel alan `| null`.
- Şemanın zaman damgaları her zaman satırda (zorunlu).
- Create'te model default'u olan alan opsiyonel (BE doldurur).

## Thunk'lar ve hook'lar

```ts
// store/thunks/transactions.thunk.ts (kullanıcı)
export const transactionsThunks = createTransactionsThunks({
  listDefaults: { page: 1, limit: TRANSACTIONS_PAGE_SIZE },
  afterUpdate: (result, _arg, { dispatch }) => {
    if (result.isSuccess) dispatch(getDashboardPortfolio());
  }
});
export const { fetchTransactionsList, fetchTransactionsById, updateTransactions, deleteTransactions } = transactionsThunks;
```

- Thunk adları: `fetch<E>List`, `fetch<E>ById`, `create<E>`, `update<E>` (`{ id, data }`), `delete<E>` (id).
- Hook'lar: `listDefaults`, `after<Op>` (başarı sonrası dispatch vb.), `mapRow` (list / getOne cevabındaki her satıra; ör. eski kayıtları normalize etmek), `requestOptions` (operasyon başına host header'ı: `{ create: { headers: { premiumUx: 'paywall' } } }`).
- Kapalı bir normal operasyonun yerine özel uç (ör. transactions `custom-create`): özel servis fonksiyonu + özel thunk kullanıcı dosyasında, aynı adla (`createTransactions`).
- Liste argümanı `Get<E>ListBody & { append?: boolean }`: `append` sonraki sayfayı ekler ve istek `skipLoading` ile gider.
- Hook'lar fabrikaya verildiği için kendi modülünün thunk'larını import döngüsü olmadan dispatch edebilir.
- Hata: interceptor'ün reddettiği `LocalResponse` fulfilled olarak döner (`isSuccess: false`); case'ler state'e dokunmaz.

## Slice

```ts
// store/slices/notifications.slice.ts (kullanıcı)
type NotificationsState = NotificationsBaseState & { unreadCount: number };
const initialState: NotificationsState = { ...notificationsInitialState, unreadCount: 0 };
const NotificationsSlicer = createSlice({
  name: 'notifications',
  initialState,
  reducers: { ...notificationsBaseReducers },
  extraReducers: builder => {
    addNotificationsBaseCases(builder, notificationsThunks);
    builder.addCase(readAllNotifications.fulfilled, state => { state.unreadCount = 0; });
  }
});
```

- **RTK kuralı:** bir action için tek `addCase`, ve `addCase`'ler `addMatcher`'lardan önce (ikisi de çalışma anında hata fırlatır; `tsc` yakalamaz). Kullanıcı dosyasında sıra: `add<E>BaseCases` → kendi thunk'larının `addCase`'leri → üretilmiş thunk'ın action'ına ek davranış `builder.addMatcher(thunk.fulfilled.match, …)`.
- List: sayfa bilgisi + `append`. getOne: `currentItem`. Create: başa eklenir (varsayılan sıra en yeni önce), `total + 1`. Update: listede ve `currentItem`'da `merge<E>Saved`: cevap alanları üstüne yazılır, id'si değişmeyen ilişki populate edilmiş haliyle kalır, değişen `{ id }` olur (sonraki okumada dolar). Delete: id thunk argümanından (`data` `null`), `total - 1`.

## Auth

Backend manifest'inde `workspace.auth` varsa (Generator'ın kurduğu host) `generateClientModules` ortak auth katmanını da üretir ([../backend/auth.md](../backend/auth.md)). `auth` seçeneği: verilmezse manifest'ten okunur (`clientAuthFromManifest`: modüller + önek, Python `/api/v1`, diğerleri `/api`); `false` kapatır; `{ modules, prefix, storagePrefix? }` elle verir. `AUTH_STORAGE_PREFIX` bir kez yazılınca sabittir: `auth.service.generated.ts` varsa içindeki önek korunur (klasör adı değişse de oturum / tema anahtarları kaymaz).

| Dosya | İçerik |
| --- | --- |
| `services/auth.service.generated.ts` | Tipler, `AUTH_ENDPOINTS`, uç fonksiyonları; sonunda `export * from './auth.service'` |
| `services/auth.service.ts` | K: projeye özel uçlar |
| `store/thunks/auth.thunk.generated.ts` | Ortak thunk'lar (`login`, `restoreSession`, `logout`, `changePassword`, modüller) + K'nın `authExtension`'ı → `authThunks` |
| `store/thunks/auth.thunk.ts` | K: `authExtension = { hooks, thunks: base => ({…}) } satisfies AuthExtension` |
| `store/slices/auth.slice.generated.ts` | `createSlice('auth')` + K uzantısı → `authReducer`, `authActions`, `authSelectors`, `GetAuthState`, `sessionChanged` |
| `store/slices/auth.slice.ts` | K: `AuthExtraState`, `authSliceExtension` |

G her seferinde, K yalnız yoksa yazılır. **G, K'yı içine alır; projede import'lar hep `.generated`'dan.** K generated'dan yalnız `import type` alır. Host kuralı ve örnek: `src/generator-assets/cursor-rules/frontend.common.mdc` "Auth". Token saklama ve refresh: client-http `services/api/auth.generated.ts` ([§ HTTP katmanı](#http-katmanı-client-http)). Yeniden üretme: `node scripts/host.mjs client <host> <app>` (modüller + auth), yalnız auth: `client-auth`.

- Root reducer'a `auth: authReducer` (`store/slices/auth.slice.generated`).
- `api.ts` isteğe `Authorization: Bearer <state.auth.accessToken>` ekler; 401'de, `isAuthRequest(url)` değilse refresh kuyruğu bir kez dener ve isteği tekrarlar.
- Dosyalar `verbatimModuleSyntax` ile derlenir.

İki rol de girer (admin paneli yalnız `admin`'i alır).

## Preset

`clientPreset.ts`. İki preset de aynı klasör ve adları kullanır: `src/services`, `src/store/thunks`, `src/store/slices`; host'tan `API` (`@/services/api`), `LocalResponse` (`@/types`), `RootState` (`@/store`).

| Preset | İstemci | Token saklama |
| --- | --- | --- |
| `redux-rn` | Varlik360 `apps/mobile`, CeyizDefterim `apps/mobile` | AsyncStorage |
| `redux-web` | SharedFrame `apps/web`, AlphaTerminal `apps/web` | `localStorage` / `sessionStorage` |

İstek bayrakları ikisinde de axios config'inde (`skipLoading`, `skipSuccessToast`; okumalar başarı mesajı göstermez):
bütün istemciler aynı interceptor'ı kullanır ([§ HTTP katmanı](#http-katmanı-client-http)).

- `optionalAsNull` verilmezse `backendRoot` bir .NET host'u ise açık (BE boş opsiyonel alanı `null` yazar).
- URL'ler mutlak (`/api/<modül>`): host'un axios `baseURL`'ü yalnız origin'dir (`http://localhost:5080`; canlıda boş = aynı origin). Elle yazılan özel uçlar da `/api/...` yazar.

## URL

Normal router mount yolu BE'den okunur (`findNormalMountPath`: Express app dosyasındaki `app.use(…, <x>Route)`, .NET `<Entity>Endpoints.cs` `MapGroup`). Bulunamazsa `baseUrl + /<modül>` ve uyarı.

## Açık konular

- **Eski auth köprüleri:** `client-http/auth-bridge/{legacy-admin,legacy-mobile,admin-refresh,legacy-shim}` ve `assetSync.ts`'teki seçimi silinir (dört proje generated köprüde).
- **`contract-parity` dil senaryosu:** aynı isteği `Accept-Language: tr` ile iki stack'e atıp `uiMessage`'ı karşılaştırmak (host ayağa kaldırmak gerekir).
- **Veri dili alanları** (isteğin değil verinin dili; Accept-Language kuralı dışında): Alpha haber `language` (`"TR"` / `"EN"`), deep-dive prompt `languages`, üretilmiş admin CRUD'larındaki `language` kolonları (Alpha `deep_dive_reports`, SharedFrame `EventQrKits`), Varlik360 job / bildirimlerinde `deviceLanguageTag ?? 'tr'`. Her biri için değer kümesi ve varsayılan kararı verilecek.
- **admin-base yayını:** `readExportResponse`'un `fileName` okuması yayınlanana kadar export dosyası varsayılan adla iner.

- **C4 Generator arayüzü:** hedef listesi (BE / Admin / istemciler), model başına istemci + katman seçimi, generate bildirimi.
- **Uçtan uca kontrol:** Varlik360 mobile simülatörde (update sonrası satır birleştirme, delete'in kaydı gerçekten silmesi, `read-all` URL'i), SharedFrame web tarayıcıda.
